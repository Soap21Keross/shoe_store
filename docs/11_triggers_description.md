Отчет по триггерам (День 11)

1. Созданные триггеры
- trg_audit_price_change: логирует изменение цен в таблицу audit_log.
- trg_audit_order_delete: логирует удаление заказов.
- trg_update_user_timestamp: обновляет поле updated_at при изменении пользователя.
- trg_decrease_stock: автоматически списывает остатки со склада при добавлении товара в заказ.
- trg_prevent_user_delete: запрещает удаление пользователя, если у него есть заказы.
- trg_check_negative_stock: запрещает добавление отрицательного количества на склад.

2. Разница между BEFORE и AFTER
BEFORE-триггеры срабатывают до применения изменений (можно отменить операцию через RAISE).
AFTER-триггеры срабатывают после применения изменений (используются для логирования и каскадных действий).

3. Использование OLD и NEW
OLD используется для доступа к старым значениям (при UPDATE и DELETE).
NEW используется для доступа к новым значениям (при INSERT и UPDATE).
В триггере на DELETE нельзя использовать NEW, так как новой записи не создается.

5. Защита от удаления пользователя
При попытке удалить пользователя с заказами срабатывает триггер trg_prevent_user_delete, который вызывает RAISE(ABORT) и выдает ошибку. База данных откатывает транзакцию, и пользователь остается.
