Анализ представлений и индексов

Созданные представления

1. v_orders_full - объединяет заказы, пользователей и состав заказов. Выводит ФИО клиента и итоговую сумму.
2. v_products_with_stock - объединяет товары, остатки и размеры. Показывает, сколько пар каждого размера есть на складе.
3. v_user_stats - показывает статистику по клиентам: ФИО, логин и количество заказов.

Созданные индексы

1. idx_products_category - на поле category в products (ускоряет поиск по категории).
2. idx_orders_date - на поле order_date в orders (ускоряет сортировку по датам).
3. idx_orders_user_id - на внешний ключ user_id в orders (ускоряет JOIN с users).
4. idx_stock_items_product_id - на внешний ключ product_id в stock_items (ускоряет JOIN с products).
5. idx_stock_items_size_id - на внешний ключ size_id в stock_items (ускоряет JOIN с sizes).
6. idx_products_manufacturer_category - составной индекс на (manufacturer, category) (ускоряет фильтрацию по производителю и категории одновременно).

Вывод

Индексы ускоряют поиск данных, позволяя базе не перебирать все строки (SCAN TABLE), а сразу находить нужные записи (USING INDEX). Однако создание индексов замедляет вставку и обновление данных, поэтому индексировать нужно только те поля, по которым часто выполняется поиск или соединение.

Проверка обновляемости представлений

При попытке обновить представление v_simple (созданное как SELECT product_id, price FROM products) база данных выдала ошибку (или обновление прошло успешно, если VIEW простое). В нашем случае представления с агрегатными функциями (SUM, COUNT) и JOIN не являются обновляемыми. Это ограничение SQLite.
