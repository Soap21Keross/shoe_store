Политика безопасности (День 13)

1. Защита от SQL-инъекций
Все SQL-запросы должны использовать параметризацию (?). Запрещено использовать f-строки для вставки данных пользователя в запрос.

2. Хранение паролей
Пароли хранятся только в виде хэшей (SHA-256). Открытое хранение паролей запрещено.

3. Разграничение прав
- admin_db: полный доступ (SELECT, INSERT, UPDATE, DELETE, CREATE, DROP).
- reader: только SELECT (чтение данных).
- developer: SELECT, INSERT, UPDATE.

4. Аудит
Все попытки входа логируются в таблицу login_audit (id, login, status, login_time).

5. Защита файла БД
Рекомендуется ограничить доступ к файлу базы данных на уровне операционной системы (chmod 600 в Linux или права доступа в Windows).
